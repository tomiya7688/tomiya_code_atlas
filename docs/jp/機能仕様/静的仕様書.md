# 静的仕様書

静的仕様書は、ソースを実行せずに、クラス・関数・メソッドの宣言、docstring、行番号、型注釈、同一ファイル内で解決できた呼び出し関係をMarkdownで確認する出力です。UnderstandのInformation Browserにあるsymbol情報や呼び出し関係の参照を、Code AtlasのCommon IR経由で利用できる形にします。

## 現在の使い方

```powershell
python app.py static-spec path\to\module.py --output module-spec.md
```

`--output`を省略するとMarkdownを標準出力へ表示します。フォルダーを指定すると、`.git`、`.build`、仮想環境、build／distなどの生成物・開発用フォルダーを除外し、配下のPythonファイルを再帰的に走査します。複数ファイルのsymbolや呼び出しは、それぞれのファイル内で解析します。

## 出力する情報

- module docstringと言語
- class、function、methodの種類、qualified name、公開範囲、定義行
- classの継承元
- Pythonで取得できたparameter／return annotation
- docstring
- sourceから検出した呼び出し式と、同一ファイル内で一意に解決できた呼び出し先
- 同一ファイル内で一意に解決できた呼び出し元

呼び出し元の一覧は同一ファイル内の静的解析結果です。別ファイルを横断する参照解決、動的呼び出し、実行時の振る舞いは示しません。外部symbolや曖昧な呼び出し先を解決済みとして扱いません。

## 責務境界

```text
Python Language Adapter -> ModuleIR
  -> Process service (call relationship analysis)
  -> Static Specification Generator -> StaticSpecification model
  -> Markdown Renderer
```

Generatorはparser型やMarkdown構文に依存しません。異なるLanguage Adapterが同じCommon IR情報を提供すれば、同じGeneratorへ渡せます。

## 現在の制約と拡張

- Python以外の言語とGUI連携は未対応です。
- parameter／return typeがCommon IRに存在しない言語では、その欄を出力しません。
- ファイルを横断する参照索引やmetrics rankingは別の解析機能として扱います。

Go移行では、同じCommon IRと出力契約をGo側にも実装します。Go版Python parser helperは、宣言、型注釈、docstring、行位置、呼び出し式をソースから抽出します。構文や動的な名前解決を推測で補わず、同一ファイル内で一意に確定できる呼び出しだけを解決済みとして扱います。
