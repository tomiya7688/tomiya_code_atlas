# 図の系列分割仕様

## 背景と目的

Tomiya Code Atlasは、大きな関係図を読みやすい複数の図へ分けます。分割で元の関係が見えなくなると、図を読む人が誤った構造を理解するため、分割前の意味上の関係を保持し、分割境界を図から辿れるようにします。

## 利用者から見た動作

利用者が解析を実行すると、アプリは最初に対象全体の意味関係グラフを作り、その後に図の表示範囲だけを分割します。通常図の境界には、外部参照nodeと「続き: <図名>」を表示します。複数箇所から参照されるnodeは共有図へまとめ、通常図には共有図への参照を残します。各図の配置情報には系列のroot、親、深さを保持します。

利用者は各関係図の配置情報と境界参照をたどってください。関係図の出力対象に含まれるnodeとrelationは、系列・共有図の境界参照をたどって確認できます。責務表は所有関係の要約であり、意味関係グラフの全edgeを出力する形式ではありません。sequence diagramの`maxDepth`は1図あたりの展開深さを制限しますが、省略した内部callは続きの図を生成して参照します。分割は解析結果、UML上の意味、元の関係を変更しません。

## 分割規則

1. 参照元数が設定threshold以上のnodeを共有図へ割り当てます。
2. 残りのnodeを弱連結成分に分けます。
3. 各成分は呼び出し元側のrootを基準にし、親から分岐した閉じた子枝だけを再帰的に別系列へ分けます。
4. 設定した最小子系列サイズを下回る枝は親系列に残します。単純な呼び出しchainを分割しません。
5. 同じstrongly connected component (SCC) のnodeを同じ表示groupへ配置します。cycleを含むSCC全体はfan-in thresholdに達するnodeがあっても一つの通常系列に保ちます。cycleを含まないSCC全体はfan-in thresholdに達するnodeを含む場合に共有図群へ配置します。cycleを含む枝は分割候補から外します。
6. 分割前の全edgeを解析metadataに保持します。系列または共有図の境界を跨ぐedgeは、少なくとも一方のendpoint側の図に外部参照stub付きで描き、参照先の図名を示します。
7. 共有nodeに接続するrelationは通常図と共有図の両方から辿れます。
8. 系列の親子関係はroot名、parent root、depthで追跡できます。

## 設定

- 参照元数のthresholdはpartitionを呼び出す側から指定します。
- 最小子系列sizeはpartition APIから指定します。図生成の既定値は3 nodeです。
- 最大node数による分割は将来の設定項目であり、この仕様の現行動作には含めません。

thresholdを変更しても意味関係グラフのnodeとrelationは変わりません。変更の効果は、分割数、境界stub、配置metadataにだけ現れます。

## 実装契約

`go/internal/analyzers` は、意味解析から得たrelation graphを受け取り、`GraphPartition.OriginalEdges` に全edgeを保持します。`BoundaryEdges` は系列間または共有図境界のedgeと両端の配置先を保持します。Analyzerはrenderer構文を生成しません。

`go/internal/generators` は、論理図に境界stubと参照先を追加します。`go/internal/renderers` は論理modelの外部参照を各出力形式へ描きます。図の分割は表示上の関心事であり、意味関係グラフの構築と別の段階です。

## 確認方法

開発者は `go test ./internal/analyzers ./internal/generators ./internal/renderers` を `go/` で実行してください。cycle、fan-in、branch、深さ上限のfixtureを確認し、sequence bundle内のcall edgeと続き図を合わせた結果が入力graphのedgeを保持することを検証してください。図の変更を受け入れる前に、MermaidとPlantUMLでstubと「続き」参照を確認してください。Windows配布EXEの実出力は、repository rootで `build_exe.bat` を実行した後、`\.venv\Scripts\python.exe tools\go_cli_smoke.py .build\dist\tomiya-code-atlas.exe` を実行して確認してください。このsmoke testはGo CLIの系列分割と境界relationも検証します。Go EXE workflowはparser helperとCLIの全smoke testが成功した後に配布artifactを保存します。
