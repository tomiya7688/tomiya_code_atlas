# 設計評価

## 目標

Tomiya Code Atlasが生成する構造情報を使い、software設計の品質を評価します。

生成した図を読みづらくする要因自体が設計上の問題を示すことがあります。そのため評価では見た目だけに頼らず、測定できるgraph／構造特性を使います。

## 候補となる指標

- couplingとdependencyの集中
- fan-in／fan-out
- cyclic dependency
- class／package間の責務の広がり
- 過大なhubまたはgod object
- call graphの複雑さ
- 過度に絡み合ったdiagram cluster
- 1つのsubsystemだけが使うclassの孤立
- 多数から共有される基盤class

## ルール

- 生のmetricと評価／scoreを分離する。
- 説明可能なscoreを優先し、各warningの根拠となる構造情報を示す。
- 1つのmetricだけを設計不良の確定根拠にしない。
- evaluator専用parserを作らずanalyzerの結果を再利用する。

## 出力

関係するclass／module／edgeを参照できるmetric、finding、任意のscoreを出します。
