# 現状

この文書は、リポジトリに現在ある機能を簡潔に示す索引です。仕様書ではありません。主要な機能や制約が変わったときに更新します。

## 現在の基盤

- `Src/languages/` に Python（主対象）、C#、C++、GDScript、Java、Go の言語アダプターがあります。コメント用アダプターのほか、Python固有のアクティビティ図・タイミング図・ユースケース図向け処理があります。
- 共通解析モデル／IR、コールグラフ解析、クラス・オブジェクト・パッケージ・コンポーネント・デプロイメント間の関係、分割処理、CIワークフロー解析が `Src/analyzers/` と `Src/models/` にあります。
- `Src/generators/` には、コールグラフ、クラス・オブジェクト・シーケンス・コミュニケーション・パッケージ・コンポーネント・デプロイメント・状態遷移・タイミング・ユースケース図、フローチャート、責務表、コメントの各生成器があります。
- Pythonファイルまたはプロジェクトから、宣言・型注釈・docstring・行番号・同一ファイル内の呼び出し関係を載せる静的仕様書Markdownを生成できます。
- Mermaid（一部PlantUML）レンダラー、責務表、設計品質Markdown、CIグラフの出力が `Src/renderers/` にあります。
- `Src/evaluators/` には、決定的なCI品質チェックとグラフ構造に基づく設計品質評価があります。
- アプリケーション処理サービス、契約、設定、データ処理は `Src/process/` と `Src/data/` にあります。Tkinter GUIの入口は `Src/ui/` です。
- 自動テストはコールグラフ、複数言語のコメント生成、図表、CI解析・評価、設計品質、契約、コンテキストツール、配布物のスモークテストを対象にしています。
- Go版の最小CLIは `go/cmd/tomiya-code-atlas/` にあり、`build_exe.bat` はGo版Windows EXEをbuildします。解析機能は移植開始前のbootstrap段階です。
- 既存機能を持つPython版は移行中の参照・テスト用ソースです。Go版配布物からPythonを起動せず、Python EXEやwheelもbuildしません。
- CIはPython 3.11 / 3.12 / 3.13でpytest全体、アーキテクチャポリシー、UPD Commanderポリシー、自己解析スモークを実行します。
- `scripts/dev/next_issue.bat` と `scripts/dev/pull_request.bat` が、IssueからPRまでの低コンテキストな作業手順を提供します。
- `scripts/dev/context.bat` / `context.sh` から、リポジトリ情報、リモート差分、簡潔な差分、構造索引、検証計画、ポリシーチェック、Context Packを利用できます。

## アーキテクチャの方向性

- 言語固有の解析は言語アダプターの内側に置きます。
- 共通IRを言語に依存しない解析の受け渡し境界にします。
- 解析・生成・評価と出力形式の描画を別の責務に保ちます。
- UI / Process / Data の境界は、Tomiya向けに適用したUPD Commander Base Designに従います。
- CommanderとMessengerは、実処理ではなくオーケストレーション／通信を担います。
- 図表出力はMermaidを既定とし、ほかの形式はRendererの境界内に置きます。

## 既知の制約と作業中の項目

- UML生成器や設計評価器の多くは実装済みですが、完成度、GUI連携、受け入れ確認は引き続きIssueで管理しています。
- 製品本体をPythonからGoへ段階移行中です。既存Python版とGo版の機能差は移行Issueと共有fixtureで管理します。
- GUIでは、ファイルと操作の互換性や対応機能モデルの整備を続けています。関連する未完了Issueを参照してください。
- アーキテクチャポリシーチェッカーは、確定した違反とレビュー用の警告を区別します。移行中のコードについて、機械判定できないルールまで自動的に証明したようには扱いません。
- 言語ごとのバックエンド（AST／意味解析エンジン）の選定や整備は、引き続きIssueで管理します。

## 現在の上位目標

1. 共通IRと依存境界を安定させる。
2. リポジトリ全体を読み直さなくても、人とAIが作業できる状態を保つ。
3. 共通の解析基盤を一度実装し、図表・表・CI解析・設計評価で再利用する。
4. 言語、UI、保存形式、Rendererの依存を交換可能な境界に置く。
