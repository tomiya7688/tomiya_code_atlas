# コメント生成の構成

この文書はPython実装におけるコメント生成pipelineの正本を説明します。

## 正規モデル

共有comment候補の契約は `Src.models.comments.CommentCandidate` の1種類だけです。

候補が保持するのは、ソース書き換え用に正規化したmetadataと提案コメントだけです。

- 対象の種類
- 対象名
- ソース行
- インデント
- 提案する文章

言語parserのAST／syntax nodeオブジェクトをこの境界より上へ漏らしません。

## 通常の処理pipeline

CLI / GUI / `ApplicationService` が使う通常経路:

```text
ソーステキスト
  -> CommentAdapter
  -> ParsedSource[CommentCandidate]
  -> CommentGenerator
  -> CommentTextBackend
  -> ソース書き換え
```

各責務:

- `CommentAdapter`: 言語別にソースを調べ、候補を抽出する。
- `ParsedSource` / `CommentCandidate`: 正規化された境界モデル。
- `CommentTextBackend`: adapterを変えずに提案コメントを差し替えたり保持したりする。
- `CommentGenerator`: オーケストレーション、言語選択、backend呼び出し、ソースへの挿入。
- `ApplicationService`: I/Oを伴うオーケストレーションのみ。

既定の `RuleBasedCommentBackend` はadapterが決定的に提案した文章を保持します。将来LLM等のtext backendを注入しても、言語adapterを変更せずに済むようにします。

## Common IR helper

`RuleBasedCommentGenerator` の責務はより限定されています。

```text
ソーステキスト
  -> Common IR LanguageAdapter
  -> ModuleIR
  -> RuleBasedCommentGenerator
  -> CommentCandidate
```

これはCommon IRから候補への純粋な変換helperです。ソースをparseしたり、言語adapterやtext backendを選択したり、ソースファイルを書き換えたりしません。

Pythonの `apply_python_comments()` は、このIR由来の経路における互換／ソース書き換えhelperとして残します。同じ正規 `CommentCandidate` を使い、別の候補型は定義しません。

## 境界ルール

- 候補の正本は `Src.models.comments.CommentCandidate` です。
- Generator、Language、Processに別の `CommentCandidate` dataclassを定義しません。
- コメントadapterはCommon IRの `LanguageAdapter` ではなく `Src.process.contracts.CommentAdapter` を実装します。
- Common IRはデータのみを保持し、コメント生成の振る舞いを持ちません。
- 言語固有parserの型は該当言語のadapter内に留めます。
- text backendの交換にadapterの変更を必要としません。
- インデントや挿入行など、ソース書き換え用metadataはCommon IRではなくcomment candidateの境界に置きます。

## 互換性

Python、C#、C++、GDScript、Java、Goの既存コメント生成は、製品の `CommentGenerator` 経路に残します。Common IR helperは再利用と適合性確認のためにあり、別の製品pipelineとして競合しません。
